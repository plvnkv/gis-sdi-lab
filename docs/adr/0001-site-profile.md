# Профіль майданчика

Погоджено окремий MAAS, один фізичний GIS-вузол і NAS для копій. Початковий доступ до GIS внутрішній.

| Дані до розгортання | Від чого залежать |
|---|---|
| CPU, RAM, архітектура, кількість та серійні номери дисків | Образи, розмітка, локальні томи, ліміти |
| BMC, VLAN, PXE, власник DHCP, DNS і TLS | Commissioning, керування та ingress |
| Протокол NAS, пропускна здатність, snapshots, retention | Запис та відновлення копій |
| Початковий обсяг і приріст даних, RPO/RTO, строк заміни вузла | Розмір дисків, частота backup та приймання |
| GitHub owner/repository, команда рев’юерів | Публічний репозиторій, CODEOWNERS, правила main |

## Стартовий профіль для слабкого обладнання

Ціль — внутрішній пілот із малим набором даних, невеликою кількістю одночасних запитів і одним імпортом за раз. Це бюджет для перевірки, а не виміряна місткість.

| Вузол | Стартовий бюджет |
|---|---|
| GIS | 4 фізичні ядра x86-64 з AVX2, BMI2 і FMA, 16 ГБ RAM, SSD 512 ГБ, 1 GbE, PXE та сумісне віддалене керування живленням. Один SSD допустимий для пілота. Виділити окреме монтування для даних. Відмова SSD вимагає відновлення з NAS. |
| MAAS | 2 ядра, 4 ГБ RAM, SSD 64 ГБ, 1 GbE з доступом до сегмента PXE. Один region+rack і локальна БД. |
| NAS | Окремий пристрій з 1 GbE. Вільний простір розрахувати для двох повних наборів копій, накопичених змін і запасу на відновлення. Окремі облікові дані для запису копій та керування історією. |

Початкові налаштування для профілю — один екземпляр кожного сервісу, один паралельний Celery worker slot, Prometheus із retention 7 днів і Loki monolithic із retention 3 дні. Для метрик і логів задати окремі дискові бюджети. RustFS single-node single-disk використовується для пілота з невеликими некритичними даними. Профіль перевіряється імпортом контрольного набору, паралельною видачею векторних і растрових тайлів та копіюванням на NAS. Перед робочим запуском перевірити OOM, тиск на диски, затримки та відновлення. Зафіксувати виміряні RPO/RTO.
